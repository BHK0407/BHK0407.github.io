🛠️ Xử lý lỗi hỏng file .dll

Trước đây mình có viết một bài hướng dẫn về cách fix về tình trạng msvcrt.dll, tuy nhiên sau vài lần điều tra thì mình thấy bài trước đó còn sơ sài nên mình sẽ tinh gọn lại trên website này.

Lần gần nhất mình may mắn phát hiện được một vài máy POS base Windows OS bán hàng (ở công việc mình đang làm cho một công ty Retail) bị các lỗi mà một số chức năng bình thường không sử dụng được.

❗ Triệu chứng

  • Khi mở một chương trình, bạn gặp thông báo lỗi như:

"The code execution cannot proceed because msvcrt.dll was not found. Reinstalling the program may fix this problem."
"The application was unable to start correctly (0xc0000005). Click OK to close the application."
  • Không mở được một số Windows Applications (Control Panel, Ease of Access, IE components…)
  • Một số chức năng hệ thống bị treo / crash
  • Không thể boot ISO để repair

⚠️ Tình trạng trước khi phân tích sâu

Thật ra khi gặp phải sự cố này lần đầu trên các máy, mình cảm thấy hoang mang và hi vọng rằng các công cụ AI có thể tìm cách để xử lý. Mình đã thử làm các bước cơ bản theo hướng dẫn trên cộng đồng Microsoft, tuy nhiên đều không khả thi. Việc mình lưu tâm nhiều nhất đó là nó luôn đề cập về CBS.log

Trước khi đi vào kiểm tra CBS.log, đã thử các phương pháp truyền thống nhưng không khả thi:

  • ❌ sfc /scannow → “Windows resource protection found corrupt files but was unable to fix some of them”
  • ❌ DISM /Online /Cleanup-Image /RestoreHealth → không resolve triệt để
  • ❌ Repair bằng ISO → không thực hiện được (không boot được ISO)

👉 Vì vậy mình quyết định kiểm tra file này đang chỉ điều gì:

Phân tích log chi tiết (CBS.log) để xác định file hệ thống bị lỗi cụ thể

🔍 Phân tích CBS.log

Từ khóa cần tìm:

  • Expected
  • Cannot Repair

Theo những gì được nêu thì:

  • Expected: hash/version đúng mà hệ thống mong đợi
  • Actual: file hiện tại bị lệch hoặc corrupt
  • Cannot Repair: Windows không thể tự sửa file đó

🔍 Nguyên nhân

  • File hệ thống (.dll) bị:
    • corrupt (hỏng)
    • missing (thiếu)
    • mismatch version
    • Hoặc có thể ảnh hưởng khi sử dụng một phần mềm bị gán mã độc

Ví dụ với case trên, ta xác định được một vài file dll đang báo lỗi: accessibilitycpl.dll, ieframe.dll, msvcrt.dll.

Mình thử tìm nguồn để tải các file này từ: www.dll-files.com. Tuy nhiên sau khi tải thành công, copy file vào không thể thực hiện. 

copy <dll-filenames> C:\Windows\System32\
Access is denied

Vì sao bị Access is denied?

  • Các file DLL thuộc hệ thống
  • Chủ sở hữu là TrustedInstaller
  • Admin cũng không ghi đè được

🔧 Cách xử lý

Bước 1: Take ownership

takeown /f C:\Windows\System32\<dll-filenames>

Bước 2: Cấp quyền

icacls C:\Windows\System32\<dll-filenames> /grant administrators:F

Bước 3: Thay thế file

copy <dll-filenames> C:\Windows\System32\<dll-filenames>

Bước 4: Verify

sfc /scannow
DISM /Online /Cleanup-Image /RestoreHealth
gpupdate /force
shutdown /r /t 5

Restore quyền hệ thống

icacls C:\Windows\System32\<dll-filenames> /setowner "NT SERVICE\TrustedInstaller"

Sau khi chạy lại sfc /scannow, kiểm tra lại CBS.log

Góc nhìn của mình

Trong trường hợp này, các phương pháp truyền thống không mang lại hiệu quả. Do đó, cần phân tích CBS.log để xác định chính xác file lỗi.

Sau khi xác định được, áp dụng phương pháp take ownership, cấp quyền và thay thế DLL.

Tuy nhiên cần lưu ý: phương pháp này chỉ nên dùng khi không còn cách khác, và mục tiêu là khôi phục tạm thời để backup dữ liệu.

📜 PowerShell Script: Phân tích CBS.log

Script giúp phát hiện DLL lỗi và hiển thị summary.

PowerShell 

        $logPath = "C:\Windows\Logs\CBS\CBS.log"
if (!(Test-Path $logPath)) {
    Write-Host "Log not found!" -ForegroundColor Red
    exit
}

$lines = Get-Content $logPath -ErrorAction SilentlyContinue
$pattern = "(?:\\\?\?\\)?([A-Z]:\\[^\s]+?\.(dll|mui|exe))|['""]([^'""]+\.(dll|mui|exe))['""]"
$errors = $lines | Where-Object {
    $_ -match "Repairing corrupted file" -or $_ -match "Cannot repair"
}

$rawResult = foreach ($line in $errors) {
    if ($line -match $pattern) {

        $file = if ($matches[1]) { $matches[1] } else { $matches[2] }

        [PSCustomObject]@{
            Time   = ($line -split ",")[0]
            File   = $file
            Status = if ($line -match "Cannot repair") { "Failed" } else { "Repaired" }
            Detail = $line
        }
    }
}

foreach ($item in $rawResult) {
    if ($item.Status -eq "Failed") {
        Write-Host "$($item.Time) | $($item.File) | FAILED" -ForegroundColor Red
        Write-Host "  $($item.Detail)" -ForegroundColor Magenta
    }
    else {
        Write-Host "$($item.Time) | $($item.File) | Repaired" -ForegroundColor Green
    }
}

$summary = $rawResult | Group-Object File | ForEach-Object {

    $failedItems = $_.Group | Where-Object { $_.Status -eq "Failed" }

    [PSCustomObject]@{
        File        = $_.Name
        Status      = if ($failedItems) { "Failed" } else { "Repaired" }
        Count       = $_.Count
        FailedLines = if ($failedItems) {
            ($failedItems.Detail -join "`n")
        } else {
            ""
        }
    }
}

Write-Host "`n=== SUMMARY ===" -ForegroundColor Yellow

foreach ($item in $summary) {
    if ($item.Status -eq "Failed") {
        Write-Host "$($item.File) | FAILED ($($item.Count))" -ForegroundColor Red
        Write-Host "  --- Failed Details ---" -ForegroundColor Yellow
        Write-Host $item.FailedLines -ForegroundColor Yellow
    }
}

$hasFailed = $summary | Where-Object { $_.Status -eq "Failed" }

if (-not $hasFailed) {
    Write-Host "`nSYSTEM STATUS: ALL CLEAN" -ForegroundColor Green
}
else {
    Write-Host "`nSYSTEM STATUS: DLL FILES DETECTED" -ForegroundColor Red
}
